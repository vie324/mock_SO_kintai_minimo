A. HPB 2ページ運用

1つの店舗がホットペッパービューティのページを2枚持つ場合。ページごとにサロンボードのログインが別なので、 連携も紐付けも2本必要になります。最優先は予約の重複を止めることで、 片方に予約が入ったら、もう一方の同じ枠を自動で閉じます（常時有効・ON/OFFなし）。

HPB連携（設定）1画面 — PC

追加連携でページを増やし、スタッフ／メニュー／設備をマトリクスで紐付ける。未設定だと重複防止が効かない。

HPB連携・PC1280px 開く
/settings/external/hpb
「HPB紐付け設定」から追加連携。行=SalonOne側／列=連携ページのマトリクス。

予約表（PC）1画面 — PC

どちらのページから入った予約かを色と斜線レールで区別し、重複が起きていたら警告する。

予約表・PC1280px 開く
/schedule
「表示するページ」を1枚に絞ると、自動で閉じた枠が斜線で出ます。

B. オフ と オプションの提案

ネイルとまつげエクステは、付いているものを外すか（オフ）で所要時間と料金が変わります。 いまはメニュー名に「自店オフ無料」などと書いて運用していますが、システムは何も知りません。 オフはメニューごとに必須で聞き、オプションは強制リンクごとに任意で提案する形にしました。 どちらも所要時間を変えるので、日時を選ぶ前に聞きます。

メニュー設定1画面 — PC

メニュー編集に「オフの確認」を追加。タブ「オフ・オプション」にマスタを置く。

メニュー設定・PC1280px 開く
/settings/menus
編集ボタンからモーダル。設定の結果を「予約フォームでの見え方」で並べて確認できます。

強制リンク設定1画面 — PC

強制リンクごとに「予約時にオプションを提案する」を設定。右にお客様の画面のプレビュー。

強制リンク設定・PC1280px 開く
/settings/templates/force-links
「編集」で詳細へ。チェックを変えると右のプレビューがその場で変わります。

予約フォーム（強制リンク・お客様向け）1画面 — スマホ / PC 兼用

メニュー → オフ（必須）→ オプション（任意）→ 日時。オフを選ぶまで日時は開かない。

予約フォーム・スマホ390px 開く
/f/:slug
オフやオプションで所要時間が延びると、入らなくなった枠が△になります。
予約フォーム・PC幅1280px 開く
/f/:slug
同じ1ファイル。画面下の「表示するフォーム」で、提案あり／なしを切り替えられます。

ファイル構成
  • screens/ … 9ファイル。勤怠・売上・予約フォームは、それぞれ1ファイルでPC・スマホ両対応
  • assets/hpbdata.js … HPB連携のダミーデータ（連携ページ・紐付け・予約・ページ間ブロック）
  • assets/menudata.js … メニュー／オフ／オプション／強制リンクのダミーデータ
  • assets/salesdata.js … 売上のダミーデータ。日次・スタッフ別の合計は必ず一致するようにしてあります
  • assets/shell.js / shell.css … サイドバー＋上部バー。移植先は app/(admin)/layout.tsx 相当
  • assets/tokens.css … 色などのCSS変数だけ。tailwind.config の theme に1対1で対応する
  • assets/base.css … リセットと共通パーツ（ボタン・カード・タグ・モーダル・トースト）
  • assets/attendance.js … DOMに触らない純粋関数。移植先は utils/attendance.ts
  • assets/mockdata.js … ダミーデータ。移植時はAPIレスポンスに置き換わる
  • assets/mockbar.js … 移植対象外。ロール／GPS／休憩／固定残業を切り替えるレビュー用足場
  • assets/logo*.png … 支給いただいたロゴ。logo-light.png は濃色サイドバー用に白へ置換したもの
仕様・データモデル案・API案・未決事項は claude_code_handoff.md にまとめてあります。
