# SalonOne 改善モック

SalonOne の **HPB 2ページ運用**、**ネイル／アイの「オフ」とオプション提案**、
**打刻・勤怠管理**、**minimo連携枠のスマホ操作**、**売上ダッシュボード** の改善案を検証するUIモックです。

素の HTML + CSS + JS で、**ビルドも依存ライブラリもありません**。

## なぜ素のHTMLなのか

移植先は Next.js App Router / next-intl / Tailwind ですが、**モックはHTMLのままが安全**です。

- エンジニアはどのみち TSX で書き直します。モックの仕事は
  「**どう動くか・どう見えるか**を曖昧さなく伝えること」であって、コードの供給ではありません
- React + Tailwind で書くと、既存のコンポーネント・i18n・型定義と噛み合わないコードが
  「本物っぽく」見えてしまい、そのまま貼られる事故が起きます
- HTML ならビルド不要で、ディレクターも含め誰でもすぐ開けます

そのうえで**移植の継ぎ目だけは実装に合わせて**あります。

| モック | 移植先 | 内容 |
|---|---|---|
| `assets/attendance.js` | `utils/attendance.ts` | 表示フォーマットと集計。ほぼコピペで移せる |
| `assets/tokens.css` | `tailwind.config` の theme | CSS変数と1対1 |
| `assets/mockdata.js` | APIレスポンス | データの形 |

時刻は全画面で「**0:00からの経過分・整数**」で保持しています。`Date` や `"09:15"` 文字列を
計算に使っていません。この方針は移植後も維持してください。

## A. HPB 2ページ運用

1つの店舗がホットペッパービューティのページを2枚持つケース（ヘア／美容整体のページと
ネイル＆アイのページなど）への対応です。ページごとにサロンボードのログインIDが別なので、
**店舗 : 連携ページ = 1 : N** で持ちます。

### 追加連携と紐付け

`HPB連携` の一覧で、複数ページの店舗は店舗名の横に「2ページ」バッジが付き、
下の行にサブページがぶら下がります。「HPB紐付け設定」を開くと

1. **連携ページ** … 登録済みのページと「＋追加連携」（ログインID・パスワード → 認証 → マスタ取得）
2. **スタッフ／メニュー／設備のマトリクス** … 行 = SalonOne側、列 = 連携ページ

が出ます。マトリクスにしたのは、**重複と独立の関係が一覧で読めるのはこの形だけ**だからです。
ページごとのタブにすると「スタッフAは両方、スタッフBはサブだけ」が絶対に見えません。

### セルの3状態 ★設計の肝

| 状態 | 意味 | 対応 |
|---|---|---|
| 紐付け済み | HPB側のIDと結んである | 不要 |
| このページには出さない | 意図的に載せていない | 不要 |
| **未設定** | まだ決めていない | **要対応** |

「出さない」と「未設定」を分けているのは、**重複防止の成否がここで決まる**ためです。
未設定だと、予約が入っても相手ページの閉じるべき枠のIDが分からずブロックできません。
2状態にすると、この2つが同じ見た目になり事故の原因が追えなくなります。

ページを1枚足すたびに全員を手で選ぶのは現実的でないので、列ヘッダーの ▾ に
「候補名で自動紐付け」「すべて“出さない”」を入れています。
自動紐付けは名前の一致で埋めるだけで、当たらなかった行は未設定のまま残します
（HPB側が `MIURA` のような表記のことがあり、完全自動にすると別人の枠を閉じかねないため）。

### ページ間ブロック（重複防止）

**常時有効です。ON/OFFの設定は作っていません。**
片方のページに予約が入ったら、もう一方の同じスタッフ・同じ時間帯を自動で閉じます。

| 状態 | 意味 |
|---|---|
| 反映済み | 相手ページの枠は閉じている |
| 未反映 | 次の同期で閉じる（現行10分間隔）。**この隙間が重複の発生源** |
| ブロック不可 | 紐付け未設定。閉じるべき枠が分からない |

### 予約表での見分け方

ブロックの色は「**どこから入った予約か**」に割り当てています。

| 流入元 | 色 |
|---|---|
| 本ページ（HPB） | 緑 `#2E8B5F` |
| **サブページ（HPB）** | **藍 `#4A3AA7` ＋ 左端に斜線のレール** |
| minimo | 金 `#B4740B` |
| 直接入力・強制リンク | ティール `#106258` |

現行は色が「新規／予約中」を表していますが、その情報はブロック内の「新規」「会員」タグと
重複しています。色は1つの意味にしか使えないので、**タグで言えていない情報**に割り当て直しました。
色だけに頼らないよう、サブページには斜線レールとページバッジ「ネ」を併用しています。

「表示するページ」を1枚に絞ると、そのページのカレンダー（HPB側から見た状態）になり、
自動で閉じた枠が斜線のバーで出ます。ブロックが効いていることを目で確認できます。

ダミーデータには**原因の違う重複を2件**入れてあります。

| ケース | 原因 | 直し方 |
|---|---|---|
| 三浦 17:00–18:30 | 同期ラグ中に両ページへ着信 | 同期間隔を詰めるしかない |
| 下條 11:00–13:00 | サブページが紐付け未設定 | 紐付ければ起きない |

> 右下の「モック設定」で **「HPB 2ページ運用」をOFF** にすると、現行（1ページ）の見え方になります。

## B. ネイル／アイの「オフ」とオプションの提案

### 現状の課題

メニュー一覧を見ると、オフの条件がメニュー名に書き込まれています。

```
【NEW OPEN記念】ワンカラー（ご新規様/自店オフ無料）¥6500→¥4800
```

名前に書いてあるだけなので、システムは何も知りません。結果として

- 他店オフのお客様が「自店オフ無料」のメニューを取ってしまう
- オフの15〜30分が枠に入らず、後ろの予約が押す
- 会計時にオフ代を手で足す（足し忘れる）
- 同じメニューを「自店オフ版」「他店オフ版」と2本持つ羽目になる

が起きます。ホットペッパーはメニュー作成時に「オフを聞く／聞かない」を選べるので、
同じものを SalonOne 側にも持たせます。

### どこで決めるか

| | 決める場所 | 予約時 | 選ばないと |
|---|---|---|---|
| **オフ** | メニュー設定「オフの確認」 | **必須** | 次に進めない |
| **オプション** | 強制リンク設定「オプションの推奨」 | 任意（提案） | そのまま進める |

分けているのは、同じメニューでもフォームによって出し分けたいからです。

- 新規集客のフォーム … 単価を上げたいのでオプションを積極的に出す
- LINE配信の再来フォーム … 予約完了まで短くしたいので出さない

メニュー側は「**何が付けられるか**」、強制リンク側は「**今回それを勧めるか**」で、
実際に出るのは両方の AND です。

### 予約フォームの順番 ★ここが実装に効く

```
メニュー  →  オフ（必須）  →  オプション（任意）  →  日時  →  お客様情報
```

オフもオプションも所要時間を足します。**所要時間が決まらないと空き枠を計算できない**ので、
必ず日時より前に置きます。日時のあとに置くと、選び直すたびに枠を取り直すことになり、
「さっき空いていた枠が無くなった」という一番嫌な体験が起きます。

そのため、**オフを選ぶまで日時の欄はロック**し、理由を書いています。
また、オフやオプションで所要時間が延びて入らなくなった枠は、黙って消さずに
`△`（所要時間が延びて入りません）で出し、「所要時間が◯分になったため◯件が入らなくなりました」と
明示します。

### オフの選択肢

店舗ごとのマスタで、ジャンル別に1セット持ちます（メニュー設定 > オフ・オプション タブ）。

| ネイル | 料金 | 時間 |
|---|---|---|
| オフしない | — | — |
| 自店オフ | ¥0 | +15分 |
| 他店オフ（ジェル） | +¥1,100 | +20分 |
| 他店オフ（スカルプ） | +¥2,200 | +30分 |

アイのセットはホットペッパーの実画面に合わせてあります
（オフしない／エクステ付替えオフ ¥0・10分／LEDから通常エクステ付け替えオフ ¥1,100・10分）。

## 直している不具合

### 最優先：時間表記の小数バグ

現状 `合計 8h43.7166666666667m` のように小数のまま表示されています。
API が `work_minutes: 523.7166666666667` を返し、フロントがそのまま描画しているためです。

対処は二段構えです。

1. **API側で秒を切り捨てて整数分で返す**（本命）
2. **フロントは必ず `fmtHM()` / `fmtJa()` を通す**（保険。float が来ても壊れない）

`assets/mockdata.js` のダミーデータは、現行APIが返している float をそのまま入れてあります
（`brk: 61.1666666666666643`）。画面で `1:01` と出ていれば丸めが効いている確認になるので、
**整数に直さないでください**。

> このバグは他の改修と切り離して先に出すのが安全です。

### その他

| 課題 | 対処 |
|---|---|
| 退勤未打刻の行が「—」で終わり気づけない | 行を赤地＋バッジ、上部にアラート集約、そこから絞り込み |
| スタッフ絞り込みがない | 月／スタッフ／状態の3フィルタ＋スタッフ単位の小計 |
| 打刻を修正できない | 行から修正モーダル（理由必須・履歴に残す） |
| スマホで横スクロールになる | 768px未満はカードレイアウトへ（CSSのみ） |
| minimo枠がスマホで閲覧専用 | タップ編集・ハンドル伸縮・長押し新規 |

### minimo連携シート

スタッフ名の下の **「minimo連携」** をタップすると、画面下部にシートが開きます。

| タブ | 内容 |
|---|---|
| 連携枠 | その日の枠一覧。「調整」で予約表の編集モードへ。枠の追加もここから |
| 直前割引 | 掲載メニュー一覧から直前割を作成。サロンIDのコピー、Minimoを開く導線も |

直前割の作成では、割引率（10/20/30/50%）を選ぶと割引後価格がその場で出ます。
対象の連携枠と公開タイミングを選んで作成すると、未同期バッジが付きます。

**枠ごと動かす操作は入れていません。** 伸縮は上下ハンドルのみです。
ブロック本体のドラッグに移動を割り当てると、スマホでは縦スクロールと競合して
意図しない移動が起きやすいためです。

### 売上ダッシュボード

現行UIからの主な変更は次のとおりです。

| 変更 | 理由 |
|---|---|
| 「入金売上」→**「総売上」** | ご指示 |
| カードを**入金ベース / 消化ベース**の2グループに分割 | 6枚を横一列に並べると、性質の違う2つの数え方が混ざっていることが読み取れない |
| 総売上に**内訳バー**（新規／継続／物販） | 構成比をその場で読めるように |
| **表示項目の設定**を追加 | 物販・回収分・口コミなど、店舗によって使わない項目があるため |
| **日次推移グラフ**を追加 | 24日分を24行の数字で読むしかなく、傾向が掴めなかった |
| 「集計対象」を表の**▼から外に出した** | 操作方法にツールチップが要る時点で、置き場所が間違っている |
| キャンセル「28 / 0」を**2つの数値に分割** | スラッシュ区切りでは何と何かが読めない |
| スタッフ名列と合計行を**固定** | 列が多く、横スクロールすると誰の行か分からなくなる |

**表示項目**は右上のボタンから開きます。プリセット（シンプル／標準／すべて）付きで、
店舗ごとに保存される想定です。鍵のかかった項目（総売上・スタッフ名など）は、
外すと画面の意味が変わるため常に表示します。

#### グラフの配色

ブランド色をそのまま系列色にすると彩度が低く、塗りが灰色に見えるため検証で不合格になりました。
彩度を上げたうえで検証スクリプトに通し、以下を確定しています。

| 系列 | 値 |
|---|---|
| 新規 | `#008874` |
| 継続 | `#BE8A24` |
| 物販 | `#4A3AA7` |

ティールとプラムの組み合わせは**2型色覚でΔE 2.5**となり判別できないため不採用にしました。
色だけに依存しないよう、凡例と直接ラベルを併用しています。

> このモック群は現行プロダクトに合わせて**明るいテーマのみ**です。
> グラフだけダークに切り替わると、暗い背景で検証した色を明るい背景に乗せることになるため、
> テーマ切替は入れていません（ダーク用の検証済みの値はソースのコメントに残してあります）。

### GPS打刻

現行の位置情報エラー（ブラウザで拒否された場合）の表示と再取得ボタンは踏襲しています。
そのうえで状態を4通りに整理しました。

| 状態 | 表示 | 打刻 |
|---|---|---|
| 範囲内 | 緑。店舗からの距離と許可範囲 | できる |
| 範囲外 | 赤。店舗からの距離 | ロック |
| 位置情報エラー | 赤。再取得ボタン付き（現行と同じ） | ロック |
| 店舗設定でGPS未使用 | カードを出さない | 常にできる |

GPSを使わない店舗があるため、**店舗ごとのオン/オフ**を `SHOP.gpsEnabled` として持たせています。
設定場所は 設定 > 管理設定 > 店舗管理 が自然だと思いますが、実装時に要確認です。

### 固定残業（みなし残業）

サロン・整体院は固定残業で回している店舗が多いため、月あたりの上限に対する消化状況を出します。

| 状態 | 条件 | 表示 |
|---|---|---|
| 通常 | 上限内 | 緑のバー |
| 注意 | 上限の80%以上 | 黄色のバー＋「残り◯時間」＋アラート帯 |
| 超過 | 上限超え | 赤のバー＋「◯時間 超過」＋アラート帯＋KPI |

アラート帯の「該当だけ表示」で、注意・超過のスタッフだけに絞り込めます。

設定は `SHOP.fixedOvertimeMinutes`（既定30時間）と `SHOP.overtimeAlertRatio`（既定80%）。
**0 にすると固定残業なしの運用**になり、バーもKPIもアラートも出ません。

> 固定残業は雇用形態ごと・スタッフごとに違う可能性が高いです。設定単位は所定労働時間と
> 同じ論点なので（メモ §5-6）、あわせて決めてください。

ダミーデータは 三浦さんが超過（32時間／30時間）、佐藤さんが注意（26時間／30時間）になるよう
1か月分入れてあります。右下の「モック設定」で上限を45時間に変えると両名とも通常になります。

### 休憩機能のオン/オフ

休憩を管理しない店舗があるため、店舗ごとの設定にしています（`SHOP.breakEnabled`）。

OFFのとき:

- 打刻画面から休憩開始／休憩戻りのボタンが消え、**出勤・退勤の2ボタン**になる
- 勤怠一覧から休憩列・休憩合計KPI・CSVの休憩列が消える
- **実働 = 退勤 − 出勤**（休憩控除なし）
- 修正モーダルの休憩欄も消える

保存済みの休憩分は消しません。設定を戻せば元の値に戻ります。

### シフトの利用

シフトが取得できるため、**退勤が未打刻の日はシフト終了時刻を修正モーダルの初期値**に入れています。
打ち直しの手間が減り、修正理由も書きやすくなります（`assets/mockdata.js` の `shiftOf()`）。

## 位置づけ

- ここにあるのは**モック**です。プロダクトのコードではありません
- データはすべてハードコードされたダミーで、通信は一切しません
- CSV出力だけは実際にファイルを生成します（BOM付きUTF-8・CRLF・整数分）
- 打刻のボタン制御は「押させない」ためのものです。**サーバー側でも同じ検証が必要**です
